# 1. Arquitetura atual

Escopo analisado em 19/08/2026:

    /home/arthur-zanon/Área de trabalho/Projetos/CertificadosSecretaria

Esta análise descreve a árvore local atual. Nenhum arquivo da aplicação foi alterado.

Arquitetura confirmada:

- Frontend administrativo: React 19 + TypeScript + Vite. O build ocorre no estágio Node 20 de deploy/Dockerfile.web e o resultado estático é servido pelo Nginx.
- Backend administrativo: FastAPI/Uvicorn, pacote certificados_backend, porta interna 8000.
- Consulta pública: FastAPI/Uvicorn + Jinja2, pacote certificados_consulta, porta interna 8001.
- Banco: PostgreSQL 16.14 Alpine, serviço db, sem porta publicada no host.
- ORM: SQLAlchemy 2.0.52. Não existe Prisma.
- Migrations: Alembic, revisões lineares 0001 a 0011. O banco observado está em 0011 (head).
- Worker: serviço worker, processo certificados-worker residente, consumindo fila durável no PostgreSQL a cada 2 segundos. Não usa Redis.
- Web/proxy: serviço web, Nginx não privilegiado na porta interna 8080, única publicação externa.
- Storage LAN: bind mount ./runtime/storage para /data/storage no admin/worker e somente leitura no consulta. PDFs ficam em /data/storage/pdfs.
- Banco persistente: volume Docker certificados-local_postgres_data.
- Autenticação: usuário/senha no PostgreSQL, bcrypt e JWT em cookie HttpOnly; SameSite=Lax e Secure=false no HTTP LAN. Sessões são revogáveis e persistidas.
- PDF: Pillow, fontes e template empacotados; QR aponta para PUBLIC_VALIDATION_BASE_URL/validar/<codigo>.
- Upload: planilha .xlsx, limite LAN de 10 MB e 2.000 linhas.
- Google Drive: implementado, mas desativado e bloqueado pelo perfil local_server, que exige STORAGE_PROVIDER=local.
- Backup LAN: backup.sh gera dump PostgreSQL, tar.gz do storage e tar.gz de configuração/secrets.
- Containers: aplicação roda como UID 10001; Nginx como UID 101; PostgreSQL com usuário da imagem oficial.

Serviços reais do compose.local-server.yaml:

| Serviço | Função | Porta interna | Porta no host | Persistência |
| --- | --- | ---: | ---: | --- |
| db | PostgreSQL | 5432 | nenhuma | certificados-local_postgres_data |
| migrate | Alembic + seed | nenhuma | nenhuma | transitório |
| admin | API administrativa | 8000 | nenhuma | banco + runtime/storage |
| consulta | consulta pública | 8001 | nenhuma | banco + storage somente leitura |
| worker | fila de emissão | nenhuma necessária | nenhuma | banco + runtime/storage |
| web | Nginx + SPA + proxy | 8080 | HTTP_PORT, padrão 80 | imagem |

EXPOSE 8000/8001 aparece nos metadados das imagens, mas não existe HostPort para essas portas.

Limites: db 0,50 CPU/512 MB; admin 0,50/512 MB; consulta 0,50/384 MB; worker 0,50/512 MB; web 0,25/128 MB. O máximo somado é 2 GB. Recomenda-se 4 GB; em 2 GB, monitore o build/runtime e considere swap administrada pelo sistema.

Fluxo exato de ./deploy.sh:

    deploy.sh
      -> entra na raiz do projeto
      -> carrega scripts/local_server_env.sh
      -> exige .env.local-server
      -> resolve LOCAL_SECRETS_DIR

# 3. Instalação do servidor

Os comandos apt são exatos para Ubuntu LTS suportado. Como o destino foi descrito apenas como Linux, confirme:

    cat /etc/os-release
    uname -m

Se ID não for ubuntu, não use o repositório ubuntu do Docker. Em Ubuntu:

    sudo apt update
    sudo apt upgrade -y
    sudo apt install -y ca-certificates curl git openssl tar gawk ufw iproute2 iputils-ping

Docker pelo repositório apt oficial:

    sudo install -m 0755 -d /etc/apt/keyrings
    sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
    sudo chmod a+r /etc/apt/keyrings/docker.asc

    sudo tee /etc/apt/sources.list.d/docker.sources >/dev/null <<EOF
    Types: deb
    URIs: https://download.docker.com/linux/ubuntu
    Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
    Components: stable
    Architectures: $(dpkg --print-architecture)
    Signed-By: /etc/apt/keyrings/docker.asc
    EOF

    sudo apt update
    sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
    sudo systemctl enable --now docker
    sudo docker run --rm hello-world
    sudo docker version
    sudo docker compose version

Autorize o operador:

    sudo usermod -aG docker "$USER"

Saia da sessão SSH e entre novamente. Depois:

    id -nG
    docker version
    docker compose version

O grupo docker equivale a acesso administrativo; inclua só operadores confiáveis.

Confirme rede:

    ip -4 addr
    ip -4 route

O firewall abaixo assume LAN 192.168.2.0/24. Se a rota mostrar outra máscara, ajuste antes. Garanta que a sessão SSH atual vem da rede permitida.

    sudo ufw default deny incoming
    sudo ufw default allow outgoing
    sudo ufw allow from 192.168.2.0/24 to any port 22 proto tcp comment 'SSH LAN'
    sudo ufw allow from 192.168.2.0/24 to any port 80 proto tcp comment 'Certificados HTTP LAN'
    sudo ufw enable
    sudo ufw status verbose

Não crie allow para 5432, 8000 ou 8001.

Portas Docker podem contornar UFW. Aqui só web publica 80; banco/APIs não publicam porta. Verifique:

    sudo ss -ltnp
    docker ps --format 'table {{.Names}}\t{{.Ports}}'

Não pode existir 0.0.0.0:5432, :8000 ou :8001.

Esperado:

    APP_ENV=local_server
    HTTP_PORT=80
    LOCAL_SERVER_URL=http://192.168.2.192
    POSTGRES_USER=certificados
    POSTGRES_DB=certificados
    STORAGE_PROVIDER=local
    LOCAL_SECRETS_DIR=./secrets/local-server

Se o IP mudar, edite LOCAL_SERVER_URL antes do primeiro deploy. ADMIN_FRONTEND_URL, PUBLIC_VALIDATION_BASE_URL e CORS_ALLOWED_ORIGINS derivam dela.

Não altere POSTGRES_USER/POSTGRES_DB após gerar secrets ou inicializar o volume. Identificadores aceitam letras, números e underscore e começam por letra/underscore.

Gere secrets:

    ./scripts/bootstrap_local_server_secrets.sh

Ele cria secrets/local-server em 0700, preserva arquivos existentes e gera:

- postgres_password: 32 bytes aleatórios em hexadecimal;
- database_url: PostgreSQL interno db:5432;
- jwt_secret;
- document_hash_keyring JSON v1;
- batch_payload_keys JSON com chave AES de 32 bytes;
- admin_initial_password digitada sem eco.

Arquivos ficam 0644 para containers não-root; o diretório 0700 impede acesso de outros usuários do host.

A senha inicial deve ter ao menos 6 caracteres, maiúscula, minúscula, número, especial, não ser comum, não conter admin e ter no máximo 72 bytes UTF-8. O bootstrap só rejeita vazio; o backend valida a política completa.

    find secrets/local-server -maxdepth 1 -type f -printf '%f %m\n' | sort
    stat -c '%A %a %n' secrets/local-server

Esperados: admin_initial_password, batch_payload_keys, database_url, document_hash_keyring, jwt_secret e postgres_password.

Secrets sobrevivem ao reboot. secrets/, .env.local-server e runtime/ estão no .gitignore. Nunca mostre valores nem envie ao Git.

Antes do deploy: .env obrigatório; Docker e porta livres; bootstrap explícito é recomendado. Não crie banco, volume, storage, migrations ou containers manualmente.

Depois do primeiro login:

- altere a senha em Perfil;
- remova/comente no .env as linhas ADMIN_INITIAL_USERNAME, ADMIN_INITIAL_NAME, ADMIN_INITIAL_ROLE e ADMIN_INITIAL_PASSWORD_FILE;
- mantenha secrets/local-server/admin_initial_password, pois o Compose o monta;
- rode ./deploy.sh e confirme a nova senha.

O seed inicial não força troca automaticamente; essa etapa é manual.

# 9. Google Drive

Ativado por padrão? NÃO.

O perfil define APP_ENV=local_server, STORAGE_PROVIDER=local e /data/storage. validate_local_server_storage() recusa outro provider. Não basta trocar para google_drive; serviços falhariam. Isso impede o deploy LAN de depender de OAuth.

Sem Google funcionam emissão, worker, PDF, storage, downloads, consulta e backup.

Para ativar futuramente: domínio/HTTPS, perfil de produção, Drive API/Picker, consentimento, cliente OAuth Web, origem/callback exatos, credenciais separadas de escrita/leitura e validação em staging.

Variáveis reais:

- STORAGE_PROVIDER=google_drive;
- GOOGLE_DRIVE_AUTH_MODE=oauth_user ou service_account;
- GOOGLE_DRIVE_CERTIFICATES_FOLDER_ID (opcional/legado);
- GOOGLE_PICKER_CLIENT_ID;
- GOOGLE_PICKER_CLIENT_SECRET ou _FILE;
- GOOGLE_PICKER_API_KEY ou _FILE;
- GOOGLE_PICKER_APP_ID;
- GOOGLE_DRIVE_OAUTH_REDIRECT_URI;
- GOOGLE_DRIVE_UPLOAD_PRINCIPAL_EMAIL;
- GOOGLE_DRIVE_PUBLIC_READER_EMAIL;
- GOOGLE_ADMIN_OAUTH_TOKEN_JSON_BASE64 ou _FILE;
- GOOGLE_PUBLIC_OAUTH_TOKEN_JSON_BASE64 ou _FILE;
- alternativas GOOGLE_ADMIN_SERVICE_ACCOUNT_JSON_BASE64/_FILE e GOOGLE_PUBLIC_SERVICE_ACCOUNT_JSON_BASE64/_FILE.

Escopos: drive.file para escrita e drive.readonly para leitura.

Google exige HTTPS para redirect URI Web e não aceita IP bruto; localhost é exceção. http://192.168.2.192 não serve. Callback deve coincidir exatamente. Sem domínio/HTTPS, mantenha local.


# 10. Backup

Monte disco/NAS externo em /mnt/backup:

    findmnt /mnt/backup
    df -h /mnt/backup
    sudo mkdir -p /mnt/backup/certificados
    sudo chown "$(id -u):$(id -g)" /mnt/backup/certificados
    sudo chmod 0700 /mnt/backup/certificados

Execute:

    cd /opt/certificados
    ./backup.sh /mnt/backup/certificados

Gera:

- postgres-AAAAMMDD-HHMMSS.dump: pg_dump custom sem owner/ACL;
- storage-AAAAMMDD-HHMMSS.tar.gz: runtime/storage;
- config-AAAAMMDD-HHMMSS.tar.gz: .env e secrets.

umask 077 protege arquivos; mantenha diretório 0700. Config é sensível. Tamanho não é fixo: dump comprimido + storage comprimido + poucos KB. Meça:

    du -sh /mnt/backup/certificados
    ls -lh /mnt/backup/certificados
    docker compose --env-file .env.local-server -f compose.local-server.yaml exec -T admin du -sh /data/storage

Verifique, substituindo timestamp:

    tar -tzf /mnt/backup/certificados/storage-AAAAMMDD-HHMMSS.tar.gz | head
    tar -tzf /mnt/backup/certificados/config-AAAAMMDD-HHMMSS.tar.gz
    docker compose --env-file .env.local-server -f compose.local-server.yaml exec -T db \
      pg_restore --list < /mnt/backup/certificados/postgres-AAAAMMDD-HHMMSS.dump | head

Restore seguro: servidor limpo/isolado. backup.sh não tem subcomando restore. Não sobrescreva servidor ativo.

No servidor de recuperação, com mesmo checkout e sem volume:

    cd /opt/certificados
    test ! -e .env.local-server
    docker volume inspect certificados-local_postgres_data

O último deve informar volume inexistente; se existir, pare.

    tar -tzf /mnt/backup/certificados/config-AAAAMMDD-HHMMSS.tar.gz
    tar -xzf /mnt/backup/certificados/config-AAAAMMDD-HHMMSS.tar.gz -C /opt/certificados
    chmod 0600 .env.local-server
    chmod 0700 secrets/local-server
    chmod 0644 secrets/local-server/*
    mkdir -p runtime
    tar -xzf /mnt/backup/certificados/storage-AAAAMMDD-HHMMSS.tar.gz -C runtime

    docker compose --env-file .env.local-server -f compose.local-server.yaml up -d db

    until docker compose --env-file .env.local-server -f compose.local-server.yaml exec -T db \
      sh -ec 'pg_isready -U "$POSTGRES_USER" -d "$POSTGRES_DB"' >/dev/null; do
      sleep 2
    done

    docker compose --env-file .env.local-server -f compose.local-server.yaml exec -T db \
      sh -ec 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --no-owner --no-acl' \
      < /mnt/backup/certificados/postgres-AAAAMMDD-HHMMSS.dump

    ./deploy.sh
    curl --fail http://127.0.0.1/api/health/ready
    docker compose --env-file .env.local-server -f compose.local-server.yaml exec -T admin alembic current

Não usa migrate reset, drop database, down -v ou remoção de volume. Para servidor populado, restaure isoladamente e faça troca controlada.

# 14. Troubleshooting

## Não abre pelo navegador

    docker compose --env-file .env.local-server -f compose.local-server.yaml ps
    curl -v http://127.0.0.1/health
    sudo ss -ltnp

Causas: web unhealthy, porta 80 ocupada, URL/IP incorreto. Veja logs; não abra 8000/8001.

## Ping funciona, HTTP não

    sudo ufw status verbose
    sudo ss -ltnp '( sport = :80 )'
    docker compose --env-file .env.local-server -f compose.local-server.yaml logs --tail=200 web

Causas: UFW, Nginx, conflito ou VLAN. Libere 80 só ao CIDR correto.

## Docker não inicia

    sudo systemctl status docker --no-pager
    sudo journalctl -u docker -n 200 --no-pager
    df -h

Ative com systemctl enable --now docker; resolva disco/instalação sem apagar volumes.

## Permissão Docker

    id -nG
    ls -l /var/run/docker.sock

Use usermod -aG docker "$USER", saia/entre. Não chmod 777.

## PostgreSQL unhealthy

    docker compose --env-file .env.local-server -f compose.local-server.yaml logs --tail=200 db
    docker compose --env-file .env.local-server -f compose.local-server.yaml exec -T db \
      sh -ec 'pg_isready -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
